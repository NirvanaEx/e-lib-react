- **Зачем:** оба компонента заменены на `DashboardLayout`, который сам собирает разделы «Администрирование» и «Управление» с проверкой прав. Поиск по всему репозиторию (`grep -rn "ManageLayout\|AdminLayout"`) находил только строки их собственных объявлений — ни импортов, ни ссылок по строке.

- **Как проверить:** `grep -rn "AdminLayout\|ManageLayout" apps packages --include=*.ts --include=*.tsx` — пусто; `npm run build --workspace apps/web` проходит.

- **Как проверить:** `grep -rn "userLibraryTableLayouts" apps` — пусто; `npm run build --workspace apps/web` проходит.

- **Зачем:** `ensureSeeded(key)` уже возвращает строку из `guides` (и существующую, и только что налитую), но её результат отбрасывался, а следом делался ещё один `getGuideRow(key)` за тем же самым.

### 5. Параллельные запросы вместо последовательных при фильтре по категориям
- **Файл:** `apps/api/src/modules/files/files.service.ts:2083`
- **Зачем:** для каждой выбранной категории в фильтре выполнялся отдельный рекурсивный CTE `getCategoryScopeIds` строго по очереди, хотя запросы независимы друг от друга.
- **Что изменилось для пользователя или для кода:** было N последовательных обращений к БД при фильтре по N категориям (в расширенном поиске их выбирают пачкой), стало одно ожидание на все N. Порядок id в итоговом `whereIn` сохранён — результат выборки тот же.
- **Как проверить:** `npm run build --workspace apps/api`; в браузере — расширенный поиск по файлам с выбором нескольких категорий, включая вложенные, выдаёт тот же список.

## Не делал

- **Мёртвый эндпоинт `GET /user/requests/access-options`** (`apps/api/src/modules/files/file-requests.user.controller.ts:41`) — после удаления клиентской обёртки у него не осталось вызовов из веба, но это публичный HTTP-эндпоинт: снаружи его может дёргать что-то, чего я не вижу. Удаление ручки — отдельное решение, не для этого прогона.
- **Экспорт `GET /dashboard/stats/files/:id/activity`** — та же история, что и выше: клиента у него больше нет, сам эндпоинт оставлен.
- **48 существующих ошибок `tsc --noEmit` в `apps/web`** — они были в проекте до меня (сборка идёт через `vite build`, который тип не проверяет). Это не уборка лишнего, а отдельная задача, и объём там заметно больше лимита прогона.
- **Экспорты, которые используются только внутри своего файла** (`clampGlassOpacity`, `fileTypeInfo`, `ICON_MAP`, `HERO_OVERRIDE_KEYS` и ещё несколько типов) — код живой, лишнее только слово `export`. Правка ничего не даёт ни коду, ни пользователю, поэтому шум.
- **Последовательные `await` в сидере и в очистке картинок инструкций** (`seed.service.ts`, `guides.service.ts:302`) — операции там пишут в БД и файловую систему, порядок может быть значим, а вызываются они редко (сид, ручной сброс). Выгоды нет, риск есть.
